# 별도 60 FPS 영상

기존 10초·24 FPS 데모의 화면과 순서를 유지하고, 프레임을 반복해 **10.000초·600프레임·고정 60 FPS(CFR)** MP4로 변환했습니다. 기존 원본은 수정하지 않았습니다. 두 영상 모두 무음이며 H.264 / yuv420p 형식입니다.

| 파일 | 해상도 | 준비된 모션 프레임 | 엔진 FPS | MP4 표시 FPS |
| --- | --- | --- | --- | --- |
| [타이포그래피](typography-ko-60fps.mp4) | 720×720 | 사전 제작 16장 | 8 | 24 → 60 |
| [골프 스윙](golf-swing-ko-60fps.mp4) | 1280×720 | AI 원본 8포즈 | 2 | 24 → 60 |

타이포그래피의 모션 구간은 원래처럼 8 FPS로 재생합니다. 골프는 첫 4초 동안 포즈당 0.50초, 이후 6초 동안 포즈당 0.75초를 유지합니다. 제목, 안내 문구, 진행 표시도 원래 영상에 포함된 화면을 그대로 사용합니다.

## 60 FPS의 의미와 한계

- 원본 영상의 각 프레임을 번갈아 **3장·2장**씩 유지합니다. 출력 n번째 프레임은 원본 floor(2n/5)번째 프레임에 대응합니다. 프레임 번호는 0부터 셉니다.
- 컨테이너의 FPS 숫자만 바꾼 파일이 아닙니다. 실제로 600프레임을 인코딩했고, 각 프레임의 타임스탬프 간격은 정확히 1/60초입니다.
- FPS 값을 늘리거나 기존 프레임을 반복하는 것만으로 새로운 움직임은 생기지 않습니다. 초당 60개의 서로 다른 글자 모양이나 골퍼 자세를 생성한 영상이 아닙니다.
- 광학 흐름, 프레임 블렌딩, AI 중간 자세 생성은 사용하지 않았습니다. 원본의 움직임 단계와 끊어지는 느낌은 남습니다. 24→60 변환의 표시 격자 때문에 일부 전환은 최대 1/120초 늦게 표시됩니다.
- 원본과 같은 화면 구성의 H.264 재인코딩이며, 압축으로 일부 픽셀 값은 달라집니다. 원본 MP4 파일 자체는 바이트 단위로 보존했습니다.
- 골프 영상은 개념 애니메이션입니다. 자세 교정이나 물리적 정확도를 보장하지 않습니다.

## 재현

저장소 루트에서 실행합니다. Python 3, Pillow, FFmpeg(libx264 포함), ffprobe가 필요합니다. 새 프로그램 다운로드나 외부 API 호출은 하지 않습니다.

```sh
python3 docs/extra-cases/60fps/reproduce.py
```

스크립트는 현재 폴더의 출력만 생성·교체합니다. 두 원본의 지정 SHA-256이 모두 일치해야 변환을 시작합니다. 검증 결과에는 실행 명령과 상대 경로가 기록됩니다. 같은 FFmpeg/libx264 버전에서는 재실행 파일의 SHA-256 일치도 검사합니다. 다른 버전에서는 인코딩 바이트가 달라질 수 있습니다.

## 검증

[verification.json](verification.json)에 다음을 기록합니다.

- 60/1 CFR, 정확히 600개 인코딩·디코딩 프레임, 10.000초, 원본 해상도 유지
- 600개 전체 PTS와 프레임 길이, 전체 영상 오류 없는 디코딩
- 원본 240프레임과 재샘플러 출력 600프레임의 픽셀 해시 대응
- 인코딩된 600프레임 전체와 대응 원본 화면의 SSIM 비교(각 프레임 0.99 이상)
- 두 원본의 변환 전후 SHA-256 일치, 결과 파일 크기·SHA-256
